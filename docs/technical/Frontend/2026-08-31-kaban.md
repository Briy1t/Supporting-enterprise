# Diagnóstico y Correcciones de Lógica en Frontend

Este documento detalla las fallas en los flujos de interacción, componentes modales y mapeo de datos dentro de la interfaz de usuario, junto con las soluciones recomendadas para el entorno cliente.

---

## 1. Módulo de Tablero Kanban

### Error al Convertir Cliente
* **Diagnóstico:** Al accionar el evento de conversión en el tablero Kanban, la función `convertirACliente` efectúa una invocación directa a la API transaccional en lugar de seguir el flujo de captura de datos.
* **Causa Raíz:** Omisión del paso de validación y enriquecimiento de datos. El frontend debe redirigir de forma obligatoria al usuario hacia la interfaz de registro mediante la ruta parametrizada `/crear-cliente?lead_id=...`. Al saltarse este paso, el backend intercepta la solicitud y genera una excepción por duplicidad de registros en la tabla.

---

## 2. Componentes de Confirmación y Notificación

### Fallo en el Modal de Envío de Contrato
* **Diagnóstico:** El sistema despliega una ventana de alerta nativa del navegador (`alert()`) al momento de procesar el despacho del documento contractual.
* **Resolución:** Remover la función nativa y enlazar el evento directamente con la ventana modular del sistema localizada en el directorio corporativo `/components/ModalConfirmacion.jsx`.

### Inicialización con Correo Vacío en Interfaz
* **Diagnóstico:** La ventana modular de confirmación renderiza un carácter de interrogación (`"?"`) en el campo del destinatario, provocando que el backend rechace la posterior petición con un error de validación HTTP `422`.
* **Causa Raíz:** La petición asíncrona previa `GET /admin/forms/{id}` falla devolviendo un código de estado `404 Not Found`. Al no recuperar el recurso, el estado de React inicializa la variable del correo como una cadena de texto vacía (`""`), rompiendo la máscara de validación del formulario.

---

## 3. Vinculación y Consistencia de Datos

### Discrepancia en el Catálogo de Servicios
* **Diagnóstico:** El componente de validación `CrearCliente.jsx` reporta de forma persistente "Servicios coincidentes encontrados: 0", impidiendo la correcta asociación de las prestaciones al dar de alta al usuario.
* **Causa Raíz:** Asimetría en los tipos de datos mapeados entre capas. El catálogo global del frontend opera y realiza búsquedas utilizando identificadores numéricos (`IDs`), mientras que el objeto contrato recuperado del backend almacena los servicios serializados como cadenas de texto plano (nombres comerciales), anulando cualquier coincidencia lógica.

---

## 4. Estrategia de Sincronización de Interfaz

### Estado Actual
El panel administrativo carece de un mecanismo de actualización automatizada, obligando al personal operativo a refrescar manualmente el navegador web para visualizar las mutaciones de estado en el pipeline.

### Soluciones Arquitectónicas Propuestas
Para subsanar la inercia visual del panel, se plantean dos alternativas técnicas de implementación en el frontend:
1. **Solución Óptima (Tiempo Real):** Desarrollar e implementar el protocolo de comunicación bidireccional mediante **WebSockets** una vez que el endpoint correspondiente sea desplegado en el servidor backend.
2. **Solución Alternativa (Corto Plazo):** Configurar un mecanismo de consulta cíclica (**Polling**) mediante un temporizador asíncrono (`setInterval`) que realice peticiones automáticas de actualización a la API cada **5 segundos**.
